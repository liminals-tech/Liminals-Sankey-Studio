Build a production-ready web application for Liminals.tech that allows users to turn ordinary spreadsheet data into professional Sankey diagrams with minimal setup.

The product must be useful both as:

1. a standalone public visualization tool;
2. a tool for content creators, trainers and business professionals who need high-quality Sankey diagrams for articles, Excel tutorials, presentations, courses and videos.

The core promise is:

Turn spreadsheet data into a Sankey diagram in seconds.

Do NOT build a generic diagramming platform.

Do NOT add AI.

Do NOT add authentication, databases, Supabase, payments, collaboration or cloud storage in this MVP.

All uploaded data must remain in the browser.

The architecture should remain suitable for a future animated Sankey mode and GIF/MP4 export, but do NOT implement video export yet.

---

TECH STACK

Use:

- React
- TypeScript
- Vite
- D3 Sankey or another mature lightweight Sankey implementation
- SheetJS/xlsx for Excel file parsing where appropriate

Keep dependencies minimal.

The application must be deployable as a static frontend on Netlify.

Do not create an Express server or any backend.

---

CORE USER EXPERIENCE

The application itself is the homepage.

Do not create a marketing landing page before the tool.

When the user opens the application:

1. immediately show a polished example Sankey;
2. provide a clear way to upload or paste data;
3. allow mapping of columns;
4. update the visualization immediately;
5. allow visual customization;
6. allow high-quality export.

The complete workflow should feel:

Upload → Map → Visualize → Customize → Export

Avoid onboarding screens and unnecessary steps.

---

DATA INPUT

Support:

- XLSX
- XLS
- CSV
- JSON
- pasted tabular data

Provide:

- drag-and-drop upload;
- file picker;
- paste-data area.

All parsing must happen locally.

Display prominently near the importer:

Your data stays in your browser.

Never send cell contents, column names or uploaded files to external APIs.

---

INPUT MODE 1 — SOURCE / TARGET / VALUE

Support traditional Sankey data:

Source | Target | Value

Example:

Revenue | COGS | 2000000
Revenue | Gross Profit | 3000000
Gross Profit | Personnel | 1200000
Gross Profit | Marketing | 500000
Gross Profit | IT | 300000
Gross Profit | Operations | 200000
Gross Profit | EBITDA | 800000

Allow the user to map:

- Source
- Target
- Value

Automatically suggest mappings based on common column names.

Aggregate duplicate Source/Target combinations.

---

INPUT MODE 2 — MULTI-LEVEL SPREADSHEET

This is a key differentiating feature.

Users should NOT need to restructure normal business tables manually.

Example input:

Business Unit | Supplier | Category | Subcategory | Spend

Allow users to define:

Level 1
→ Level 2
→ Level 3
→ optional additional levels

and select:

Value

Automatically convert hierarchical rows into the links required by the Sankey renderer.

Example:

Finance | Microsoft | Software | Productivity | 50000

becomes conceptually:

Finance → Microsoft
Microsoft → Software
Software → Productivity

weighted by the selected value.

Aggregate duplicate flows automatically.

Make the hierarchy builder easy to understand.

Allow the user to reorder selected hierarchy levels.

SANKEY VISUALIZATION

The Sankey must be the visual centerpiece.

Requirements:

- responsive layout;
- proportional flow widths;
- readable nodes;
- readable labels;
- useful hover/tap states;
- clean default spacing;
- automatic duplicate aggregation;
- graceful long-label handling;
- sensible behavior with many nodes;
- consistent values throughout the flow;
- clear highlighting of selected nodes and connected paths.

On tap or click of a node:

highlight:

- upstream links;
- downstream links;
- connected nodes.

On tap or click of a link:

show:

Source
Target
Value

Do not rely only on hover because the tool must also work on mobile.

---

LAYOUT OPTIONS

Support at least:

- horizontal Sankey: left → right;
- reversed horizontal Sankey if simple to implement.

Structure the renderer so a future vertical mode could be added, but it is not required for the MVP.

---

NODE POSITIONING

Use automatic layout initially.

If stable and reasonably straightforward, allow users to drag nodes vertically.

Do not let node dragging destabilize the application.

The basic renderer and exports are more important.

If manual movement is implemented:

- retain position during editing;
- provide Reset layout.

EXPORT

Export quality is a major product requirement.

Implement:

PNG

Support:

- current canvas dimensions;
- 2× high-resolution export;
- transparent background where appropriate.

The export must contain only the visualization canvas, including title/subtitle when enabled.

Never export editor controls.

---

SVG

Provide clean scalable SVG export.

The SVG should be useful for:

- presentations;
- articles;
- design tools;
- further editing.

---

FUTURE VIDEO / ANIMATION READINESS

Do NOT implement GIF or MP4 now.

However, design the renderer so that future data can have:

Date | Source | Target | Value

Example:

2024 | Revenue | Personnel | 100
2025 | Revenue | Personnel | 120
2026 | Revenue | Personnel | 150

A future version should be able to animate the Sankey between dates.

Therefore separate:

data input
→ parsing
→ normalization
→ Sankey model
→ layout
→ rendering
→ export

Do not tightly couple Sankey calculations to the editor UI.

Avoid architecture choices that would make frame-by-frame rendering difficult later.

---

DATA PREVIEW

After importing data, show a compact table preview.

Show:

- detected columns;
- number of rows;
- valid rows;
- ignored rows;
- numeric errors.

Do not build a spreadsheet editor.

The purpose is only to help users confirm that the correct data was imported.

---

DATA VALIDATION

Handle gracefully:

- empty input;
- missing fields;
- empty Source;
- empty Target;
- text in Value;
- zero values;
- negative values;
- duplicate links;
- circular relationships;
- self-references;
- disconnected nodes;
- very large datasets.

Never display:

NaN
Infinity
undefined

Never leave a blank visualization without explaining why.

---

CIRCULAR FLOWS

Traditional Sankey layouts may not support loops cleanly.

Detect circular relationships.

If unsupported by the selected renderer, show a clear message explaining which relationships cause the problem.

Do not silently produce an incorrect diagram.

Design the code so more sophisticated loop support could be added later.

FINAL PRODUCT PRINCIPLE

Optimize the entire application around this workflow:

Spreadsheet → Sankey → publishable visual

The application should make it possible for someone with ordinary Excel-style data to create a professional visualization suitable for a report, article, course, presentation or video without needing to understand Sankey-specific data preparation or visualization code.
